# gPTP Studio 使用指南

[English](USER-GUIDE.md) · **简体中文**

在 Linux 工作站上观察和调试 gPTP / IEEE 802.1AS。

## 当前可用状态

工程预览。规划有官方专业版，此处尚不提供购买或硬件精度保证。

## 平台与安装

仅支持 Linux，提供 x64 和 arm64 发布附件。Windows 和 macOS 不属于产品目标。真实抓包与 PHC 操作需要兼容硬件和适当权限。

从[官方 Releases](https://github.com/turinglambdaai/gptp-studio/releases)选择明确标注系统和架构的附件，阅读该版本说明并核对附带校验文件。未列出的附件或平台不视为已交付。预览构建可能没有系统发行者签名或公证；不要为安装而关闭系统安全保护。

## 第一次使用

1. 先使用确定性模拟器，确认 GTK 窗口显示示例时钟和会话。
2. 选择网卡或开启抓包前，阅读真实引擎配置与硬件资格说明。
3. 随结果保存接口、驱动、时钟源、工具版本和抓包设置，便于其他工程师复现。

## 数据、备份与恢复

抓包原件、会话输入与导出结果应独立于程序文件保存。复制活动文件前先停止抓包。抓包和诊断可能泄露 MAC/IP、网络拓扑及设备标识；公开报告使用合成样本。

## 联网、密钥与隐私

抓包会访问所选网络接口；更新和下载会访问外部服务。仅查看模拟场景时不应授予抓包或时钟控制权限。

## 已知限制

模拟器与 CI 证据不能证明网卡、硬件时间戳、linuxptp 互操作或定时精度已合格。0.4.0 起原始抓包导出和 Wireshark 回放已免费，工程报告仍有门禁；旧构建保留各自行为。

## 更新与卸载

先备份数据，再阅读目标版本说明。应用内检查更新不一定能安装当前渠道的更新；按手册区分便携包、系统安装器和源码安装。不要绕过失败的验签或用来源不明的文件覆盖程序。更新失败时保留现有数据与错误信息，使用可信发行包恢复；卸载程序通常不等于删除独立的数据目录，删除个人数据前先确认备份。

## 获得帮助

在 [GitHub Issues](https://github.com/turinglambdaai/gptp-studio/issues) 反馈，中文或英文均可。提供版本、系统与架构、安装渠道、复现步骤、预期和实际结果。先用合成样本复现；不要附上密钥、授权文件、数据库、原始私密文档或完整日志。公开支持不承诺响应时限。
